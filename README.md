# Mind Mentor — Spring Boot Backend

Production-ready backend for the [Mind Mentor](https://github.com/Mamtha-pro/DigitalMentor-3D-Tutor) React frontend, generated by reverse-engineering every `fetch()` call in the `mind-mentor` app (Notes, Study Plan, Timer, Resources, Chat/3D Tutor, Profile).

## Tech stack
Java 21 · Spring Boot 3.3 · MongoDB · Spring Data MongoDB · Spring Security + JWT · Lombok · Bean Validation · Springdoc OpenAPI (Swagger) · Maven · Ollama integration (model: `smollm`)

## Getting started

1. **MongoDB** — run locally or point at Atlas:
   ```bash
   docker run -d -p 27017:27017 --name mongo mongo:7
   ```
2. **Ollama** — install and pull the model the frontend expects:
   ```bash
   ollama pull smollm
   ollama serve   # exposes http://localhost:11434
   ```
3. **Configure** — copy the env vars below into your shell or an `application-local.yml`, or just rely on the defaults in `application.yml`.

   | Variable | Default | Purpose |
   |---|---|---|
   | `MONGODB_URI` | `mongodb://localhost:27017/mind_mentor` | Mongo connection string |
   | `JWT_SECRET` | (dev placeholder) | **Change this in production** |
   | `JWT_EXPIRATION_MS` | `604800000` (7 days) | Token lifetime |
   | `CORS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:3000` | Vite/CRA dev origins |
   | `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama host |
   | `OLLAMA_MODEL` | `smollm` | Model used for `/api/chat` |

4. **Run**:
   ```bash
   mvn spring-boot:run
   ```
   or build a jar:
   ```bash
   mvn clean package
   java -jar target/mind-mentor-backend.jar
   ```
5. **Swagger UI**: http://localhost:8080/swagger-ui.html

On the frontend, set `VITE_API_BASE_URL=http://localhost:8080` (already the default fallback in every component).

## API surface

| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/register`, `POST /api/auth/login` |
| Profile | `GET/PUT /api/user/profile` |
| Notes | `GET/POST /api/notes`, `PATCH/DELETE /api/notes/{id}` |
| Study Plans | `GET/POST /api/study-plans`, `PATCH /api/study-plans/{id}/tasks`, `DELETE /api/study-plans/{id}` |
| Study Sessions (Timer) | `POST/GET /api/study-sessions`, `GET /api/study-sessions/stats` |
| Resources | `POST /curate-resources`, `GET /curate-resources/{userId}`, `DELETE /curate-resources/{id}` |
| Web Search | `POST /web-search` |
| Chat / 3D Tutor | `POST /api/chat`, `GET /api/chat/history` |

All endpoints except `/api/auth/**` require `Authorization: Bearer <token>`, matching the `mind_mentor_token` the frontend stores in `localStorage`.

## Notes on design choices
- Mongo `_id` is exposed as `_id` (not `id`) in JSON so it drops straight into the frontend's existing `note._id`, `plan._id`, `resource._id` usage.
- `POST /api/study-sessions` returns `stats.currentStreak`, computed from consecutive days with a focus session — exactly what `Timer.jsx` reads for its completion toast.
- `/curate-resources` returns `RESOURCE_EXISTS` (409) if a topic was already curated for the user, matching the frontend's existing error handling branch.
- `/web-search` proxies DuckDuckGo's free Instant Answer API (no key needed); swap `WebSearchService` for a paid provider if you need deeper results.
- `/api/chat` builds a tutoring prompt from the message + trailing history and calls Ollama's `/api/generate` (non-streaming), then persists the exchange as a `ChatConversation` for the History panel.
